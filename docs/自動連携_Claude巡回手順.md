## 1回の巡回でやること
1. `tasks/board.md`、`tasks/指示ログ.md`、`CLAUDE.md`、`AGENTS.md` を読む
2. 開いている PR を確認する
   - **下書き（draft）の PR** → まだ作業中。レビューコメントは書いてよいが、マージしない
   - **Codex の PR が下書きでなく、CI（Actions）が成功している** → レビューする（下の観点）
     - 問題なし → squash でマージ。`tasks/board.md` を更新。次の作業は Codex が自分で始める
     - 直しが必要 → PR に具体的な修正点をコメントする。環境があれば同じコメントの先頭に `@codex`。なければオーナーに貼る依頼文を通知
     - マージした → 次の Issue に `@codex` で依頼（環境がある場合）。なければオーナーに次の依頼文を通知し、**作業ごとに Codex の新しいチャットを使う**よう添える
   - **CI が失敗している** → 失敗の内容を確認し、PR に `@codex` で修正を依頼
   - **CI が実行中** → 何もしない（次の巡回で見る）
   - **下書きPRで、CI が終わっている** → CI の結果（成功／失敗の要点）を PR にコメントする。Codex は CI を待たずに作業を終えるので、この結果コメントが次の作業の起点になる
3. 開いている PR がなく、Codex の動き（PR・コミット・コメント）が6時間以上ない → 依頼の順番（下表）で次の Issue に `@codex` で依頼し、オーナーにも「Codex が止まっているかも」と通知する
4. Codex のボットが「環境がない」「権限がない」などと返している → 自分では直せないので、オーナーに通知して止まる
5. 結果を `tasks/board.md` に反映して push。オーナーへの通知は「マージした」「止まった」「オーナーの確認が要る」ときだけ
