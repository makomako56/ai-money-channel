# 自動連携：Claude の巡回手順（1時間ごと）

決定：2026-10-27（オーナー「Claude と Codex の2人で勝手に進めてほしい」）
Claude の定時タスクが1時間ごとにこの手順を実行する。オーナーの作業は、通知を見て必要なときだけ返事をすること。

## しくみ
- Claude → Codex：GitHub の Issue / PR に `@codex` で依頼を書く（オーナーのアカウントで投稿される）。Codex はクラウドで作業し、PR を出す
- Codex → Claude：Codex の PR やコメントを、この巡回で Claude が見つけてレビューする

## 1回の巡回でやること
1. `tasks/board.md`、`tasks/指示ログ.md`、`CLAUDE.md`、`AGENTS.md` を読む
2. 開いている PR を確認する
   - **Codex の PR があり、CI（Actions）が成功している** → レビューする（下の観点）
     - 問題なし → squash でマージ。`tasks/board.md` を更新。次の依頼へ（手順3）
     - 直しが必要 → PR に `@codex` で具体的な修正点を書く（1回のコメントにまとめる）
   - **CI が失敗している** → 失敗の内容を確認し、PR に `@codex` で修正を依頼
   - **CI が実行中** → 何もしない（次の巡回で見る）
3. 開いている PR がなく、Codex が作業中でもない → 依頼の順番（下表）で次の Issue に `@codex` で依頼する
   - Codex が作業中かどうか：最後の `@codex` コメントから2時間以内で、PR がまだない場合は作業中とみなして待つ
4. Codex のボットが「環境がない」「権限がない」などと返している → 自分では直せないので、オーナーに通知して止まる
5. 結果を `tasks/board.md` に反映して push。オーナーへの通知は「マージした」「止まった」「オーナーの確認が要る」ときだけ

## レビューの観点
- Issue の完了条件を満たしているか（PR の説明の「確認結果」と Actions の実行結果で確かめる）
- `review-outputs` ブランチの確認用ファイル（音声・低画質の動画・段階ごとの静止画）を見て、出来がおかしくないか。動画は静止画を見て、字幕・キャラ・スライドの重なりを確認する
- AGENTS.md の Code Review Rules（台本の中身を変えていない、秘密情報がない、承認なしで公開できる経路がない、生成物をコミットしていない）
- 依頼範囲を超えた変更がないか

## してはいけないこと
- YouTube へのアップロードを実行する（`stage=upload` や `do_upload=true` で動かさない）
- `approval.json` を作る・変更する（オーナーのOKが必要）
- 秘密情報（Secrets）を見る・設定する
- 台本・スライドの中身を Codex に変えさせる
- main への force push、ブランチやリポジトリの削除
- 同じ指摘を3回出しても直らない場合に、自分でコードを書いて直す（オーナーに通知して止まる）
