# 音声工場（作業依頼01・01b）

GitHub Actions上のPython 3.11、CPU版音声エンジン、ffmpegを使う。Mac上でエンジンを起動する必要はない。音声生成にSecretsは不要。

## 起動と確認用コピー

```bash
gh workflow run factory.yml -R makomako56/ai-money-channel -f episode=ep000_sample -f stage=voice
gh workflow run factory.yml -R makomako56/ai-money-channel -f episode=ep000_sample -f stage=voice_samples
gh run list -R makomako56/ai-money-channel --workflow factory.yml
gh run watch RUN_ID -R makomako56/ai-money-channel --exit-status
```

通常のWAV等は従来どおり `<episode>-<stage>` artifactに7日保存する。Claudeがartifactを取得できないため、確認用コピーを **review-outputsブランチだけ** に保存する。Issue #7による生成物保存の例外であり、mainへの生成物コミットは行わない。

- [サンプル回のセリフ音声](https://github.com/makomako56/ai-money-channel/tree/review-outputs/ep000_sample/voice)：`mp3/0001.mp3` … と `timeline.json`、`engine.json`。
- [全話者・全スタイルの比較](https://github.com/makomako56/ai-money-channel/tree/review-outputs/ep000_sample/voice_samples)：`キャラ名_スタイル名_ID.mp3`、`samples.json`、`engine.json`。
- GitHubのcontents APIでも `?ref=review-outputs` を指定して取得できる。
- 各回は `<episode>/<stage>/` に保存。同じ場所の旧ファイルは削除して置き換え、別の回や別のステージは維持する。同一内容の再保存では新しいコミットを作らない。
- 確認用timelineの `review_audio` がMP3の相対パス。`wav` は元のartifact内のWAVを示し、製作用タイムラインとの対応を保つ。製作には元のWAVを使う（MP3には符号化時の遅延がある）。
- 確認用コピーは `<episode>-<stage>-review` artifactにも残す。push失敗時も元音声を取得可能。

GitHub Actionsの権限はstep単位には指定できないため、書き込みを専用の `publish-review` ジョブに分離した。エンジン設定・生成ジョブは `contents: read`、コピー保存ジョブだけ `contents: write`。トークンはpush手順にだけ環境変数で渡し、ファイルやログに保存しない。書き込み先はコード内で `review-outputs` に固定し、force pushは使わない。保存ジョブを直列化し、競合時は再取得して対象ディレクトリだけを再反映する。

## 既定の声とエンジン切り替え

オーナーの最新方針（Issue #7のコメント）に従い、**既定はAivisSpeech**。

- ミライ：まお（おちつき）
- ひなた：コハク（ノーマル）

`config/voice_engine.yaml` の `engine` だけを `aivisspeech` / `voicevox` に変更すれば、ActionsのDockerイメージ・ポート・合成先が切り替わる。

| エンジン | 公式CPUイメージ | ポート |
|---|---|---|
| AivisSpeech | ghcr.io/aivis-project/aivisspeech-engine:cpu-latest | 10101 |
| VOICEVOX | voicevox/voicevox_engine:cpu-latest（検証済みdigest固定） | 50021 |

`config/characters.yaml` の `voice.voices.<engine>.name` に `まお（おちつき）` のようなキャラ名＋スタイル名を設定する。実行時に `/speakers` からIDを解決するので、AivisSpeechの大きなスタイルIDをハードコードしない。`speaker_id` を明示した場合は互換性のため優先する。設定した声が見つからないときはエラーにして停止する。

未設定時のみ警告して仮音声を使う。VOICEVOXはNo.7／春日部つむぎ、AivisSpeechは取得した通常系スタイルから選ぶ。AivisSpeechの既定設定には上記2人を明示済み。

`voice_samples` は固定の5人に限定せず、そのエンジンの `/speakers` が返す全話者・全読み上げスタイルを同じ2文で合成する。話速1.0・音高0.0・スタイル強度1.0で比較し、全一覧とファイル対応を `samples.json` に保存する。歌声用スタイルは対象外。ファイル名のIDは同名スタイルによる上書きを防ぐ。

## 音声の調整

共通値は `voice` 直下、エンジンごとの上書き値は `voice.voices.<engine>` に置く。

| 設定 | API上の対応・動作 | 省略時 |
|---|---|---|
| speed | speedScale | 1.0 |
| pitch | pitchScale | 0.0 |
| intonation | intonationScale | ミライ1.2／ひなた1.3 |
| volume | volumeScale | 1.0 |
| pre_phoneme / post_phoneme | prePhonemeLength / postPhonemeLength | 各0.05秒 |
| pause_scale | pause_moraのvowel_lengthを乗算し、上限0.5秒 | 1.4 |

AivisSpeechは、選定時の標準設定に合わせて **話速1.0・音高0.0・スタイル強度1.0** を明示した。VOICEVOXプロファイルには従来の話速・音高と指定の抑揚1.2／1.3を設定してある。

AivisSpeechの `intonationScale` は「抑揚」ではなく「選択スタイルの感情表現の強さ」。ノーマルではエンジン側が自動選択する。また、モーラ長は非対応なので **pause_scaleは警告して無視** する。句読点や「…」を含む元のtext/kanaを保持し、自然な間はエンジンに任せる。音高を0以外にすると音質が劣化しうるため、AivisSpeechの既定は0にした。[AivisSpeech公式のAPI差分](https://github.com/Aivis-Project/AivisSpeech-Engine#voicevox-engine-との互換性について)

セリフ間は `config/style.yaml` の `audio.dialogue_gap_seconds: 0.35`、スライド切替時は `slide_gap_seconds: 0.6`（加算ではなく置換）。最初のセリフは0秒開始、最後に余分な間は入れない。各WAV内にはpre/post_phonemeも含まれ、その実測尺から開始・終了秒を決める。

読み辞書は `config/reading_dict.csv`（`表記,読み,アクセント位置`）。合成前に選択したエンジンへ登録する。ファイルがなければヘッダーだけの空辞書を作り、不正な行は行番号付きで停止する。

`engine.json` にエンジン・バージョン・声一覧・クレジット文言を記録する。指定の2人では `音声：AivisSpeech（まお・コハク）`、VOICEVOXでは使用キャラごとの `VOICEVOX:キャラ名`。動画末尾・概要欄への組み込みは後続の担当工程でこの情報を使う。

## 出力形式とCI

- 製作用WAVは24kHz・16bit・モノラルPCM。
- `timeline.json` はセリフの配列。`line`、`speaker`、`text`、`expression`、`slide`、`start`、`end`、`wav`、`voice`、`engine`、`envelope_fps`、`envelope`を含む。
- `envelope`はWAV先頭から1/30秒ごとのRMS音量（0〜1）。端数フレームを含み、無音の間はタイムライン時刻で表現する。
- 全WAVの尺、台本との一致、間、30fps包絡、無音でないことを確認する。MP3は全スタイルの一覧との一致、尺、全体のデコードを確認してから保存する。
- スライドが配置済みなので、サンプル回だけ画像確認を省略する分岐は削除した。手動の解析用 `--no-slide-check` は残す。

`ci.yml` は `pull_request` の `pipeline/**`、`config/**`、`.github/workflows/**`、`requirements.txt` 変更時に動作する。単体テストとep000のvoiceを実行し、AivisSpeech選択時は全スタイルのvoice_samplesも検証する。同じリポジトリ内のPRでは確認用コピーも保存する。forkのPRは保存ジョブを実行しない。以前の特定ブランチpushトリガーは削除した。声の選定が終わったため、一時的な `voice-trial.yml` も削除した。

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s pipeline/tests -v
python -m pipeline.script_parser episodes/ep000_sample/script.txt
```
